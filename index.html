1. Overview

WIshield ("the App", "we") is a Wi-Fi security analysis tool for Android. We built this app with a privacy-first architecture: the minimum data needed to deliver a useful security service, collected in the most anonymous form possible, with no advertising, no selling of data, and no tracking.

This policy explains exactly what data the App touches, why, where it goes, and what rights you have over it.

2. Data Collected & Stored Locally

The following is collected and stored only on your device in a local SQLite database. It is never uploaded, sold, or shared with any third party.

3. Data Shared via Community Intel (Firebase)

When you perform a deep scan, the App may upload an anonymised network fingerprint to Google Firebase Firestore to contribute to the community threat database. This powers the "Community Intel" feature that shows how a network compares against what other devices have seen.

What is uploaded — and how it is anonymised
Field uploadedAnonymisation method
Network name (SSID) SHA-256 hash only The original name is never transmitted; the hash is one-way and irreversible.
Access point MAC address (BSSID) First 3 bytes (OUI) only Identifies the hardware vendor (e.g., "Cisco", "TP-Link"), not the specific device.
Signal strength (RSSI) Raw dBm value — not personally identifiable
Wi-Fi frequency Channel center frequency in MHz (e.g., 5180)
Security type String such as "WPA2" or "OPEN"
Anonymous device ID Random UUID → SHA-256 Generated on first run; not linked to your Google account, phone number, IMEI, or any other identity. Used only for rate-limiting (max 1 upload/network/hour) to prevent database poisoning.
Scan timestamp Unix epoch integer — no timezone or locale data
What is explicitly NOT uploaded
  • Plain-text SSID (network name)
  • Full BSSID / MAC address
  • GPS coordinates, cell tower data, or any location signal
  • IP addresses (device, gateway, or DNS)
  • Any Google account information
  • Phone model, IMEI, or Android advertising ID
  • App usage patterns or analytics events

4. Anti-Poisoning & Data Integrity

The community database is protected by multiple layers to ensure no single device can inject false threat data:

  • Client-side schema validation — every record is validated for plausibility (RSSI range, MAC format, frequency validity) before upload is attempted.
  • 3-sigma outlier rejection — if your device's reading deviates more than 3 standard deviations from the community consensus, the upload is silently refused.
  • Consensus threshold — community data is only marked as "trusted" after ≥ 3 independent devices have reported the same network.
  • Server-side Firestore Security Rules — enforced by Google Firebase: immutable fields, strict field types, and monotonic report counts prevent retroactive data manipulation.
  • Rate limiting — max one upload per network per device per hour, enforced via the anonymous device ID.

7. Data Retention & Deletion

  • On-device data — retained until you uninstall the App. Uninstalling completely removes the local SQLite database and all scan history.
  • Community fingerprints in Firebase — retained indefinitely as part of the shared threat database. Because these records contain no personal information and are merged into aggregate community statistics, individual record deletion is not technically meaningful.
  • Anonymous device ID — clearing the App's data (Settings → Apps → WIshield → Clear data) generates a new anonymous ID on the next launch, making any prior uploads permanently unattributable.

8. Security

  • All communication with Firebase uses HTTPS / TLS 1.3
  • Firestore Security Rules enforce server-side validation on every write
  • No credentials, API keys, or tokens with write access to your data are stored on-device
  • The anonymous device ID is derived from a one-way SHA-256 hash and cannot be reversed
